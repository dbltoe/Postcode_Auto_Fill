Postcode Auto Fill documentation

Postcode Auto Fill v3.0.x (formerly Postal Code Automatic, by piloujp) is an encapsulated plugin for Zen Cart v1.5.8 through v3.0.0 (PHP 7.4 to 8.5) that automatically fills state, city and if available street address fields in a form when you enter postal/zip code. An Ajax request and JavaScript (jQuery) make this possible on the fly without submitting the form.
It works on the account, address book and checkout address pages, and on One-Page Checkout's checkout page (billing and shipping addresses, for guests and account holders alike).
It uses extra tables with postal codes data per countries.
An external jQuery plugin is used to display multiple possible answers in a JavaScript popup tool window:
PowerTip  from Steven Benner at https://stevenbenner.github.io/jquery-powertip/.

'Postcode Auto Fill' is provided with ten countries data/tables: United States, Spain, France and its territories, Germany, Italy, Swiss, Liechtenstein (included with Swiss), Austria, Australia and Japan. If you want to add a country, you must build a new table with necessary data and add some PHP code (in SWITCH loop) to the Ajax query function.
Instructions for that are at the end of this page.

INSTALL:

Copy zc_plugins folder content to the zc_plugins folder in your cart. Then go to Zen Cart admin menu Modules->Plugin Manager. You should now see Postcode Auto Fill in the plugin list. Click on Install button on the right. The postal codes tables to install in database are big and it may take a while. Wait (and wait more) until a success message displays.

If an older version is already installed, you should have an Upgrade button instead. Postal code table should already be install and the process will go faster. If an update is available for some tables (new post code data), the plugin installer will update database with the included files. Another possibility, for example if you messed up a table data, is to delete the old table from the database first and the installer will reinstall it.

Stores running Postal Code Automatic v2.0.x (the same zc_plugins/PostAuto folder) get the Upgrade button too: upload v3.0.0 beside the old version folder, upgrade, and the old folder can then be deleted. The postal code tables are kept.

Important notes:

  1. If your server is slow you might encounter script timeout during install. Installer already increased script execution time to 300s, but if it is not enough, you can increase this time by editing the zen_set_time_limit(300) lines in Installer/ScriptedInstaller.php or in Zen Cart admin menu Configuration->MyStore->Admin Set max_execution_time for processes. In case it already happened, see note below.
  2. Postal code tables are big, depending on countries they can have few thousand records to over 124 501 records for Japan. If the server encountered a timeout during installation, plugin won't be installed. In this case you have to run again the installer (by clicking on install button again), but before that you must delete (using phpMyAdmin for example) the last created postal code table (zones_to_post_code_jp for example) which is probably incomplete due to the timeout. Installer won't try to install again tables that are already there, only those that are missing.

USAGE:

When filling the form, it is better to start by postal code. As soon as you have entered 4 characters, the Ajax script will try to find, if exists, the postal code and data for the country actually set. When the postal code is found, the state and city are filled and eventually the street address one if there is some data.

In case there are multiple results for the city (and street address), the first on the list will be used to fill up the city field. Other possible choices are accessible through a JavaScript hover tool tips. When you mouse hover the city field, a clickable list of possible cities for the entered postal code will appear on the right.
Same goes for the street field if data are available, except here, all the options for all possible cities are displayed at first. If you click on one of the optional cities name, it will fill the city field* and the options, if available, for the street address field will be restricted to this city only.

* The Javascript PowerTip tool used here seems to have few bugs and sometime, at first use, clicking on a city name has no effects. But if you close and reopen the tip tool by moving the mouse out and in again, it should work properly.

UNINSTALL:

Like for installation, use Zen Cart's Plugin Manager in admin: Modules->Plugin Manager. You can either disable the plugin or uninstall it. Disable option will just deactivate the plugin but deletes nothing. Uninstall will delete postal code tables in database and deactivate the plugin.

Once uninstalled and you do not plan to use it again, you can save space on server by deleting folder PostAuto in Zen Cart's zc_plugins folder.

Note:

If you want to keep postal codes tables when uninstalling, you can do it by commenting out the appropriate line (in function executeUninstall()) in file zc_plugins/PostAuto/v3.0.x/Installer/ScriptedInstaller.php.

UPDATING ZONES ID:

When you add zones for a country listed in this plugin after the plugin was installed, you can update zones ids in the plugin table using this SQL query:

UPDATE zones_to_post_code_{CountryCode} AS ztp INNER JOIN zones AS z ON ztp.zone_name = z.zone_name AND ztp.zone_country_id = z.zone_country_id SET ztp.zone_id = z.zone_id;

Replace {CountryCode} by the two letters ISO code for the country you want to update. Note that the new zones names must match the data in this plugin for this to work.

BUILDING A NEW COUNTRY TABLE DATA:

- First you need to download data. First place to start is your country's national Post Office site. Be careful that there are lots of services providing postal code data, but they are not often free to distribute or even use.
- You then must format these data to build a MySQL database table with a name following this format zones_to_post_code_{2 letters country code} and with these fields at minimum:

  • zone_country_id for the country id  number used in Zen Cart. Set for the country you downloaded data.
  • zone_id for this country zones id numbers in Zen Cart if they exist. First setting it to zero is easier and then when table is created (and zones exist), update it with an SQL query like this:

    (example for United States):
        UPDATE zones_to_post_code_us INNER JOIN zones ON zones_to_post_code_us.zone_name = zones.zone_name AND zen_zones.zone_country_id = 223 SET zones_to_post_code_us.zone_id = zones.zone_id;
    (example for France and other countries that includes territories or other small countries):
        UPDATE zones_to_post_code_fr INNER JOIN zones ON zones_to_post_code_fr.zone_name = zones.zone_name SET zones_to_post_code_fr.zone_id = zones.zone_id;
    (example for Japan):
        UPDATE zones_to_post_code_jp INNER JOIN zen_zones ON zones_to_post_code_jp.zone_name = zen_zones.zone_code AND zen_zones.zone_country_id = 107 SET zones_to_post_code_jp.zone_id = zen_zones.zone_id;

  • post_code obviously for postal/zip code. This plugin is programmed for a minimum of five characters long.
  • zone_name for state, district, prefecture or whatever it is called in the country.
  • zone_city_name for city name corresponding to the postal code.
  • zone_street_name for area, county, or any street level information. This can be omitted like in US table, but it must be taken in account in PHP code in AJAX function.

Then I add a post_zone_id field as an auto_increment index. Have a look at provided tables data to get an idea of the structure. All this can be done using different tools, like Excel and/or a good text editor like notepad++ to finally build an SQL file to import in Zen Cart.
With countries using non-alphabet writing you might want to double fields (adding an alphabet written field), but it will make SQL requests and PHP loops more complicated. Have a look at Japanese version.

- Finally, few files need to be updated/created:

  • Create a new file zc_plugins/PostAuto/v3.0.x/Installer/sql/install/zone_to_post_code_{NewCountryCode}.php. Look at other files in same folder to reproduce the structure. Write the core tables as FROM zones WHERE and FROM countries WHERE; the installer adds the store's table prefix to those.
  • Update file zc_plugins/PostAuto/v3.0.x/catalog/includes/classes/ajax/zcAjaxPostcodeQuery.php. In the 'switch' loop you need to add a 'case' for the new country. You can copy an existing one and modify country code, table and columns, especially if you have street data or not ($by_city).
  • Update file zc_plugins/PostAuto/v3.0.x/Installer/ScriptedInstaller.php. In function executeUninstall(), add a line like this:
    $this->executeInstallerSql("DROP TABLE IF EXISTS " . TABLE_ZONES_TO_POST_CODE_{NewCountryCode});
  • Update files zc_plugins/PostAuto/v3.0.x/admin/includes/extra_datafiles/postcode_auto__database_names.php and zc_plugins/PostAuto/v3.0.x/catalog/includes/extra_datafiles/postcode_auto__database_names.php. add a line like this:
    zen_define_default('TABLE_ZONES_TO_POST_CODE_{NewCountryCode}', DB_PREFIX . 'zones_to_post_code_{NewCountryCode}');
